---
title: Troubleshooting
---

This guide covers a few common issues with the mobile app. If the steps below do not identify or resolve your issue, please open an issue on [GitHub](https://github.com/stumpapp/stump/issues/new/choose) and include the relevant debug information (e.g., app version, server version, etc). Please try to be thorough, it is very difficult to remotely debug a problem without sufficient information.

<Callout type="info">
	Most error pages in the mobile app include a button to open a GitHub issue with the debug info
	organized for you
</Callout>

## The app reports a server compatibility or GraphQL error

The mobile app and Stump server communicate through a GraphQL API. The app may show a compatibility error if there is some kind of version mismatch, e.g. the app is newer than the server and is asking for something which doesn't exist, or the app is too old and is not asking for something in the correct format.

Current TestFlight builds are made against the `nightly` branch, so may "break" more often if you lag on updating your server instance.

## I get validation errors when browsing my OPDS catalog

It's possible that either the app is being overly strict in its validation of a quirk in your OPDS server, or that your OPDS server is not fully compliant with the OPDS specification. Either way, please open an issue on [GitHub](https://github.com/stumpapp/stump/issues/new/choose) so we can work through the issue together.

## None of the covers or images are loading in the app

This is likely due to a misconfiguration of your Stump server. If you are running a reverse proxy, you need to instruct Stump to trust the [corresponding headers](/docs/guides/configuration/server-config#stump_trust_proxy_headers) that it may receive.

If you aren't running a reverse proxy, this is likely something else and should be reported as an issue on [GitHub](https://github.com/stumpapp/stump/issues/new/choose).
