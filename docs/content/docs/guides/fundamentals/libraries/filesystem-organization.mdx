Stump supports two different filesystem patterns for organizing your library:

- Top-Level Collections
- Recursive Series

## Top-Level Collections

Each folder at the top-most level of the library root is a single series. **Only direct descendants of the library root will be considered for series creation**, so long as they contain media files at some point in their hierarchy.

## Recursive Series

Each folder at any level recursively from the library-root is a single series. **Any descendant directories (including the library root itself) will be considered for series creation**, so long as they directly contain media files.

## Examples

A few examples to help illustrate the difference between the two library patterns and how Stump will interpret their differing structures.

### Example 1

Consider the following file tree:

<Files>
	<Folder name="Ebooks" defaultOpen>
	<Folder name="Shannon, Samantha" defaultOpen>
			<File name="The Priory of the Orange Tree.epub" />
	</Folder>

    	<Folder name="Sanderson, Brandon" defaultOpen>
            <File name="Elantris.epub" />
            <Folder name="Mistborn" defaultOpen>
                <File name="Mistborn 01 - The Final Empire (epub).epub" />
                <File name="Mistborn 02 - The Well of Ascension (epub).epub" />
                <File name="Mistborn 03 - The Hero of Ages (epub).epub" />
            </Folder>
           	</Folder>

        <Folder name="J.R.R. Tolkien" defaultOpen>
            <Folder name="The Lord of the Rings" defaultOpen>
                <File name="The Fellowship of the Ring.epub" />
                <File name="The Two Towers.epub" />
                <File name="The Return of the King.epub" />
            </Folder>
            </Folder>
            </Folder>

</Files>

When Stump scans this library as a collection-priority library, it will create 3 series:

1. _Shannon, Samantha_
2. _Sanderson, Brandon_
3. _J.R.R. Tolkien_.

When Stump scans this library as a series-priority library, it will create 4 series:

1. _Shannon, Samantha_
2. _Sanderson, Brandon_
3. _Mistborn_
4. _The Lord of the Rings_.

### Example 2

Consider the following file tree:

<Files>
    <Folder name="Comics" defaultOpen>
    <Folder name="Daredevil" defaultOpen>
            <File name="Daredevil 001.cbz" />
            <File name="Daredevil 002.cbz" />
    </Folder>

    	<Folder name="The Amazing Spider-Man (2018)" defaultOpen>
            <File name="The Amazing Spider-Man 001 (2018).cbz" />
            <File name="The Amazing Spider-Man 002 (2018).cbz" />
        </Folder>
        </Folder>

</Files>

When Stump scans this library as a series-priority library, it will create 2 series:

1. _Daredevil_
2. _The Amazing Spider-Man (2018)_.

In this particular case, a collection-priority library would produce the same result, as there are no nested folders. The representation is also identical to the file tree, above!

## Choosing a Pattern

There is no right and wrong when it comes to configuring a library as either collection-priority or series-priority. It's all about preference.

In general, if you plan on having nested folders in your library that can be grouped by the upper most level, then you should use a collection-priority library. If your library is flat, or you don't want to group books by the upper most level, then you should use a series-priority library.

Personally, I use a collection-priority library for my ebooks and a series-priority library for my comics. I find that the collection-priority library works well for ebooks, as I can group them all by author, regardless of how I organize the underlying filesystem, and the series-priority library works well for comics, as I can group them by major arcs.

## Alternative Options

Unfortunately, Stump does not support any other patterns, as there are simply too many ways to organize a library to support them all. If you have a library that doesn't quite fit either of these patterns, or you just prefer a different organization method, you can always use the [File Explorer](/docs/guides/features/file-explorer) to navigate your library. This is similar to using a native file explorer to navigate your filesystem.
